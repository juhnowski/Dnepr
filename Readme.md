# Историческая справка
Управляющая машина широкого назначения (УМШН) «Днепр», разработанная в 1961 году под руководством Виктора Глушкова, представляла собой первую в СССР серийную полупроводниковую управляющую ЭВМ. Ее архитектура строилась на принципах работы с непрерывными технологическими объектами и включала центральный процессор, память на ферритах и специализированное устройство связи с объектом (УСО).

# Архитектурные особенности и параметры
- Элементная база: Полупроводниковые диоды и транзисторы (второе поколение ЭВМ).
- Система счисления и представление чисел: Двоичная система; числа с фиксированной запятой, расположенной перед старшим разрядом.
- Разрядность: 26 двоичных разрядов.
- Структура команд: Двухадресная система команд.
- Быстродействие: Около 30 000 операций в секунду для сложения, вычитания и логических команд; около 5000 операций в секунду для умножения.
- Оперативная память: Построена на ферритовых сердечниках с базовым объемом одного блока в 512 слов, с возможностью подключения дополнительных блоков.
- Внешняя память: Накапливающее устройство на магнитном носителе (магнитной ленте) емкостью до 200 000 слов.

# Структура комплекса
- Центральная вычислительная часть: Универсальный цифровой процессор и память для обработки алгоритмов и логического управления.
- Устройство связи с объектом (УСО): Аппаратные блоки ввода-вывода для сопряжения с датчиками производственных процессов, аналого-цифровыми и цифро-аналоговыми преобразователями.

# УСО
Устройство связи с объектом (УСО) машины «Днепр» было ее главным отличием, позволяя коммутировать аналоговые каналы, преобразовывать их в цифровую форму с помощью АЦП (аналого-цифрового преобразователя) и выдавать управляющие сигналы через ЦАП (цифро-аналоговый преобразователь). В архитектуре «Днепр» команды УСО кодировались специальными опкодами (например, выбор канала и запуск преобразования), а значения напряжений кодировались в виде 26-битных чисел с фиксированной запятой (где диапазон [-1.0, 1.0) маскировался в знаковое 26-битное целое).

# Пример
Напишем программу автоматического сглаживания данных. Симулятор будет считывать показания двух разных датчиков (например, основного и резервного датчиков давления), складывать их значения и выводить накопленную сумму на исполнительное устройство через ЦАП.

# Сценарии
Добавим поддержку простого языка сценариев автоматизации (тестирования). Сценарий будет описывать, на каком шаге симуляции (итерации) какое значение должно поступить на определенный канал АЦП.
Сценарий будет считываться из текстового файла (например, scenario.txt), где каждая строка имеет простой формат: ИТЕРАЦИЯ КАНАЛ ЗНАЧЕНИЕ.
```
; Итерация  Канал  Значение
3          3      0.0
5          4      0.85
```
## Тест
Создаем ассемблерную программу program.asm и сценарий program.sco и запускаем:
```bash
cargo run -- program.asm
```
